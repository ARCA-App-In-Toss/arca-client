## 1. 제품과 사용자 맥락

ARCA는 매일 도착하는 SEMA의 기본 질문과 대체 질문 중 하나를 골라 짧게 답하고, 저장한 응답을 `기억 조각`으로 축적하는 SF 콘셉트의 자기 성찰 서비스입니다.

주 사용자는 일기는 부담스럽지만 하루 2~5분 동안 자신의 생각과 감정을 정리하고 싶은 만 14세 이상의 토스 사용자입니다. 아침, 저녁, 잠들기 전이나 반복되는 일상에서 잠시 자신을 돌아보고 싶은 순간에 사용합니다([PRD §3 · L43–62](../../docs/ARCA_MVP_PRD.md#3-대상-사용자와-이용-상황)).

UI는 다음 가치를 보존합니다.

- 질문까지 빠르게 도달하고 짧게 답해도 완결감을 느낍니다.
- 답변을 평가·진단하거나 출석을 압박하지 않습니다.
- 앱 소유 UI는 픽셀·도트의 브랜드 문법과 읽기 영역의 차분한 표현을 연결합니다. 짧은 표지·조작과 계속 읽는 문장은 역할별 서체로 구분하고, 장식 강도보다 질문·입력의 가독성을 우선합니다.
- 한 화면에는 하나의 주요 행동을 둡니다.
- 응답의 비공개성과 입력 유실 방지를 시각적 분위기보다 우선합니다.

## 2. 대상 환경과 기술 전제

- 앱인토스 **비게임 WebView 미니앱**이며 iOS·Android 실제 토스 앱을 모두 출시 환경으로 검증합니다.
- Safe Area·키보드·Android Back·플랫폼 내비게이션·네트워크 단절을 공통 제약으로 취급합니다. 320 CSS px·큰 글자·스크린 리더에서도 질문 선택·입력·저장이 가능해야 합니다.
- 승인 스택·설치 상태는 [06 §2.2 · L57–79](./06_FRONTEND_SPEC.md#22-선택한-스택과-설치-상태)을 따릅니다. 픽셀 UI 후보·도입 방식·스타일은 [06 §2.4 · L97–122](./06_FRONTEND_SPEC.md#24-픽셀-ui-선별-도입과-출처-추적) 및 [06 §2.5 · L124–131](./06_FRONTEND_SPEC.md#25-공통-스타일과-의존성-경계)가 소유합니다. 실제 버전·설치·기기 지원을 추정하지 않습니다.

## 3. 비주얼 방향

### 핵심 콘셉트

비주얼 콘셉트는 **고요한 심우주 관측실**입니다([D-UI-001 · L27](./DECISIONS.md#2-ui-overview-결정)).

| 키워드 | 화면에서의 의미 |
|---|---|
| 고요함 | 넓은 여백, 낮은 정보 밀도, 한 번에 하나의 주요 행동 |
| 심우주 | 딥 네이비 공간과 제한된 청색·시안 발광 |
| 관측 | 질문과 기억 조각을 발견하고 바라보는 명확한 정보 위계 |
| 동면과 꿈 | 느리지만 기다림을 만들지 않는 전환, 흐릿함보다 부드러운 깊이 |
| 인간적인 온기 | 쓰는 동안의 안정감과 내 문장이 보존되는 연결감, 제한된 새벽 하늘색·앰버 보조색 |
| 픽셀 조각 | 장면·아이콘·주요 행동의 정수 셀과 hard edge를 시각 서명으로 사용하고, 읽기 영역에는 여백·테두리 없는 면을 허용 |

현재 대표 시각 기준은 [ARCA 로고](../../design/logo/ARCA_LOGO.png)의 블루·시안 발광과 [인트로 서사 · L1–41](../../docs/ARCA_INTRO_STORY.txt)의 함선·동면·JOY·꿈과 기억입니다. 특정 서비스의 화면을 복제하지 않고 `심우주 관측실`, `조용한 연구 계기판`, `작은 픽셀 디오라마`를 조합한 독립적인 방향으로 설계합니다.

장면은 F01 인트로 디오라마와, 인트로 마지막 캡슐 시점을 잇는 F10 투명 캡슐 배경입니다. 유리 너머 하늘만 기기 시각 네 구간(새벽·낮·노을·밤)의 팔레트로 바뀌고 글자·조작은 반투명 디스플레이·면에만 둡니다([D-UI-095](./DECISIONS.md#114-현행-ui와-입력-표시)). 시안은 JOY, 바이올렛은 기억, 블루는 주 행동에 한정합니다. 화면 본문과 새로 나타나는 루트 탭·준비된 캡슐 배경은 같은 180ms fade로 한 번 진입합니다(D-UI-104). 텍스트 행동은 배경 없이 눌림만 표시합니다. 수치·타입·모션은 02, 화면별 정보 순서는 03, 검증 범위는 08 §14.1을 따릅니다.

### 감정 곡선

| 단계 | 목표 감정 | 시각적 역할 |
|---|---|---|
| 진입·인트로 | 낯선 정적과 참여의 이유 | 발견→함선과 동면→소이와 JOY→이유→질문과 기억→탑승으로 이어지는 건너뛸 수 있는 6장면 서사; 마지막 대화창이 사라진 뒤 탑승 행동이 나타남(D-UI-089·D-UI-104) |
| 오늘의 SEMA | 안전한 집중 | 미응답은 질문과 작성 행동을 가까이, 완료 후에는 저장 당시 질문 서문과 완료 문구, 기록 진입만 표시(D-UI-097) |
| 응답 작성 | 개인적인 온기 | 질문을 읽던 공간에서 작은 작성 영역이 열리고 내 문장이 늘어나는 만큼 확장; 비공개·기기 보관 상태를 명확히 안내 |
| 저장 성공 | 짧은 빛과 마무리 | 작은 기록 매체가 한 번 형성되고 저장 결과와 누적 수(이전 수에서 한 칸 굴러 바뀜)가 남음; 응답은 상세에서 읽음; 첫 기억은 축적 장소 발견, 반복 기록은 오늘의 마무리(D-UI-102·D-UI-104) |
| 항해 기록 | 차분한 축적과 다시 읽기 | 목록은 월 구획 안에 보조 날짜 위·흰 질문 아래 행, 끝에 가까워지면 자동으로 이어 불러옴; 상세는 날짜·질문 서문과 응답 주 읽기 영역; 수정·삭제는 보조 행동(D-UI-105) |

### 금지 표현

- 공포·폐쇄·고립감을 과도하게 만드는 장면
- 홍채 스캔, 감시 카메라, 생체 인증처럼 보이는 연출
- 지속적인 글리치, 깜빡임, 배경 별가루와 무한 반복 모션(예외: F02 기억 조각의 느린 픽셀 빛 호흡 D-UI-091, 요청 중에만 보이는 CMP-027 로더 D-UI-105)
- 연속 출석, 점수, 등급, 랭킹, 보상 상자 같은 게임화
- 답변의 감정을 색·아이콘·표정으로 해석하거나 진단하는 표현
- 본문 뒤에서 읽기를 방해하는 고밀도 우주 배경
- 픽셀 장식 때문에 질문·답변·버튼의 식별과 읽기를 어렵게 만드는 방식
- 점수, 체력·경험치 막대, 퀘스트, 아이템 슬롯과 게임 결과처럼 보이는 픽셀 UI

## 4. 테마와 플랫폼·ARCA 경계

MVP는 **ARCA가 소유하는 한 벌의 테마**를 사용합니다. 질문 → 작성 → 저장은 낮은 명도로 이어지는 방향을 채택하며, 밝은 기능 영역을 의무화하지 않습니다. 시스템 테마 자동 추종이나 테마 선택 기능을 추가하지 않습니다([D-UI-033 · L90](./DECISIONS.md#6-시각-표현과-탐색)).

- 질문·작성·저장 장면은 명도 연속성을 우선하고, 입력은 주변보다 한 단계 밝은 잉크색 기록 surface로 구분하는 기본안을 사용합니다.
- F10 캡슐 배경의 시간대 하늘은 장면 팔레트이며 테마 전환이 아닙니다. 표면·글자·조작 토큰은 모든 시간대에 같습니다.
- 정책·긴 안내 등에는 내용에 맞는 밝은 surface도 선택할 수 있습니다. 모든 문맥에서 본문·커서·입력 경계·오류·저장 상태를 직접 검증합니다.
- 픽셀 실루엣은 주요 행동·아이콘·도메인 장면에 집중하고, 읽기·보조 영역은 테두리 없는 면과 여백으로도 구분합니다([D-UI-034 · L91](./DECISIONS.md#6-시각-표현과-탐색)).
- 브랜드·제목·짧은 JOY Label·조작에는 픽셀 서체를, 질문·응답·설명·날짜·카운터에는 본문 서체(Pretendard)를 사용합니다. 실제 크기는 20/16/14px(rem 기반) 세 종류입니다([D-UI-032 · L89](./DECISIONS.md#6-시각-표현과-탐색), D-UI-088).
- 대비·큰 글자·포커스·스크린 리더는 필수 계약입니다. 구체적인 색과 장식 강도는 [00 §7.1 · L143–163](./00_INDEX.md#71-결정-강도와-자율-탐색)의 조정 가능한 기본값이며, §10의 비교 시안으로 채택값을 정합니다.

| 앱인토스 플랫폼 계층 | ARCA 앱 소유 계층 |
|---|---|
| 모든 화면 상단의 필수 Navigation | 픽셀 앱 셸, 화면 제목과 콘텐츠 surface |
| 플로팅 탭바의 필수 외곽 형식 | 탭 내부 픽셀 아이콘·레이블과 선택 상태 |
| WebView 종료·신고·문의 같은 플랫폼 행동 | Button, 입력, 목록, Dialog, Sheet, Toast와 모든 상태 |
| 플랫폼이 직접 그리는 서체·아이콘 | JOY·SEMA·기억 조각, ARCA 픽셀 아이콘과 역할별 서체 |

앱인토스가 필수로 제공하거나 형식을 강제하는 플랫폼 UI는 ARCA 픽셀 스타일로 위장하지 않습니다. 그 아래 앱 소유 영역은 TDS Mobile 컴포넌트를 사용하지 않고 ARCA 전용 픽셀 시스템으로 일관되게 구현합니다. 복잡한 포커스·스크린 리더 동작은 시각 스타일이 없는 headless primitive가 담당하고, 시각 결과와 상태 계약은 [Design System의 CMP-001~CMP-027 · L440–466](./02_DESIGN_SYSTEM.md#91-전체-목록)로 관리합니다([D-UI-009·D-TECH-050~053 · L38](./DECISIONS.md#3-design-system-결정)). 외형의 출처가 달라도 [02 §1.4 · L49–56](./02_DESIGN_SYSTEM.md#14-서로-다른-출처의-시각-통합)의 공통 픽셀 문법으로 연결합니다.

## 5. 전역 정보 구조

최상위 IA는 [Flow §1 · L13–27](../../docs/ARCA_USER_FLOW.md#1-전체-흐름)의 `오늘`, `기록`, `설정` 세 하단 탭으로 고정합니다.

| 전역 진입 | 역할 | 루트 화면 |
|---|---|---|
| 오늘 | 오늘의 SEMA 확인, 질문 선택, 응답 시작 또는 오늘 기록 확인 | F10 |
| 기록 | 저장된 기억 조각 목록 | F20 |
| 설정 | 승객 정보, 정책, 고객센터와 데이터 관리 | F30 |

하단 탭은 루트 화면인 **F10·F20·F30에서만** 표시하고, F30은 닉네임 편집 중에만 숨깁니다. 현재 탭을 다시 누르면 화면 맨 위로 이동합니다(D-UI-105). 기억 조각 누적 수는 F10·F20 제목 오른쪽에 둡니다([D-UI-094](./DECISIONS.md#114-현행-ui와-입력-표시)).

| 화면 | 하단 탭 | 화면 내 복귀 방식 |
|---|---|---|
| F00, F01, F02, F03 | 숨김 | 흐름의 주 행동 또는 플랫폼 종료 |
| F10 | 표시 | 최상위 오늘 탭 |
| F11, F12, F13 | 숨김 | 오늘 또는 명시된 다음 화면 |
| F20 | 표시 | 최상위 기록 탭 |
| F21, F22, F23 | 숨김 | 기록 목록·상세로 뒤로가기 |
| F30 | 표시(닉네임 편집 중 숨김) | 최상위 설정 탭 |
| F31 | 숨김 | 설정으로 뒤로가기 |
| F90 | 숨김 | 재시도 또는 플랫폼 종료 |

이 표는 ARCA가 그리는 하단 탭의 표시 규칙입니다. 앱인토스가 제공하는 공통 내비게이션 바를 임의로 중복 구현하거나 숨기는 근거로 사용하지 않습니다.

## 6. 전역 레이아웃

### 폭과 여백

- 최소 검증 폭: `320 CSS px`
- 콘텐츠 최대 폭: `480px`
- 기본 좌우 여백: `20px`
- 359px 이하 좌우 여백: `16px`
- 480px보다 넓은 환경에서는 콘텐츠를 가운데 정렬하고 바깥 영역은 앱 셸 배경으로 유지합니다.
- 가로 스크롤을 만들지 않습니다.

### 스크롤과 작은 화면

- 세로 스크롤을 기본으로 하며 콘텐츠를 작은 높이에 맞추기 위해 축소하지 않습니다.
- 앱 셸이 viewport를 소유하고 각 화면은 하나의 명확한 주 스크롤 영역을 사용합니다.
- 고정 헤더·하단 행동을 사용하더라도 큰 글자와 작은 높이에서 본문을 가리지 않아야 합니다.
- F11·F22의 저장은 문서 흐름 안 inline 하나입니다. 단일 조작·포커스와 상세 조건은 [03 F11 · L379–442](./03_SCREENS_SPEC.md#52-f11--응답-작성)을 따릅니다([D-UI-059 · L121](./DECISIONS.md#8-핵심-경험과-화면별-위계)).
- 질문과 답변에는 고정 높이를 사용하지 않고 줄바꿈과 내용 증가를 허용합니다. 응답 작성은 3~4줄의 기본 공간에서 시작해 페이지 흐름 안에서 확장하며, 고정 높이 상한 뒤 내부 스크롤로 전환하는 규칙을 두지 않습니다([D-UI-036 · L93](./DECISIONS.md#6-시각-표현과-탐색)).
- 버튼 레이블이 두 줄이 되거나 시스템 글자가 커져도 주요 행동이 잘리거나 겹치지 않아야 합니다.

### Safe Area

- 공통 앱 셸이 Safe Area를 한 번 받아 상단, 콘텐츠, 하단 내비게이션에 배분합니다. 값의 출처(앱인토스 SDK·CSS `env()` fallback)는 06이 소유합니다.
- 개별 화면이 임의의 기기별 padding 값을 추가하지 않습니다.
- 하단 탭과 고정 행동은 홈 인디케이터 영역 위에 배치합니다.
- 화면 모드나 Safe Area 값이 바뀌면 현재 화면을 다시 계산하되 입력값과 스크롤 문맥을 잃지 않습니다.

## 7. 키보드와 내비게이션 원칙

공통 앱 셸이 Safe Area, 키보드와 앱 라우트 계층을 중앙에서 처리합니다([D-UI-003 · L29](./DECISIONS.md#2-ui-overview-결정)).

### 소프트 키보드

- 포커스된 입력, 글자 수, 검증 오류와 저장 행동이 키보드에 가려지지 않게 스크롤합니다.
- 고정 하단 행동은 키보드가 열리면 키보드 위로 이동하거나 작성 화면의 스크롤 흐름 안으로 전환합니다.
- 키보드 열림만으로 답변을 저장하거나 화면을 이탈하지 않습니다.
- 키보드가 닫혀도 사용자의 입력, 선택 질문과 스크롤 복귀 지점을 유지합니다.

### Android 뒤로가기와 화면 복귀

Overlay·키보드·안전 이탈·부모/루트 순서와 저장 중 잠금은 [04 §5.7 · L181–200](./04_INTERACTIONS_AND_COPY.md#57-back키보드포커스--ix-017ix-018), 결과 미확인 이탈·재진입은 [04 §5.14 · L284–295](./04_INTERACTIONS_AND_COPY.md#514-저장-결과-확인과-안전한-이탈--ix-036)를 따릅니다. 저장 잠금을 키보드 닫기 금지로 확대하지 않습니다.

플랫폼이 키보드 닫기를 먼저 처리한 경우 같은 입력 한 번으로 화면까지 연속 이탈시키지 않습니다. 화면 내 뒤로가기, Android 시스템 뒤로가기와 앱인토스 내비게이션이 서로 다른 히스토리를 만들지 않도록 하나의 라우트 계층에 연결합니다.

외부 약관 전문이나 고객센터에서 돌아오면 이전 화면과 안전한 표시 상태를 복원하고, 가능하면 진입을 실행한 요소로 포커스를 돌려놓습니다.

## 8. 날짜 표현

- 오늘 화면에는 [Rules SE-03 · L51](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema)에 따라 실제 KST 날짜를 질문 패널 내부 상단에 표시합니다. 질문 라벨 외의 발신자·SEMA 코드 메타는 표시하지 않고 SEMA 식별자는 데이터에만 둡니다.
- MVP에서는 `항해 N일차`, 2999년 날짜 같은 세계관 날짜를 날짜 자리에 표시하지 않습니다. F01 서사 문장의 배경 연도는 날짜 표시가 아닙니다([D-UI-006 · L30](./DECISIONS.md#2-ui-overview-결정)).
- 날짜 변경·만료·삭제 대상처럼 오해 비용이 큰 문맥은 실제 날짜를 일반적인 한국어 표기로 보여줍니다. 개별 삭제 확인 Dialog는 날짜를 반복하지 않고, 뒤의 F21 서문이 대상 날짜를 보여 줍니다(D-UI-104, OD-30).
- 세계관 분위기는 JOY, SEMA, 기억 조각과 시각 장면으로 전달하며 실제 시간 판정을 흐리지 않습니다.

## 9. 화면 범위

MVP의 15개 화면과 목적은 [03 §3 · L103–123](./03_SCREENS_SPEC.md#3-화면-범위와-추적-지도)을 따릅니다.

- 섹션은 내부에서만 배정하고 화면에 노출하지 않습니다([Rules ON-04 · L37](../../docs/ARCA_MVP_RULES.md#2-최초-탑승과-승객), [Product Decision OD-07 · L29](../../docs/ARCA_OPEN_DECISIONS.md#최근-닫힌-결정)).
- 성별, 연령, 프로필 이미지와 원본 익명 식별키를 표시하거나 설정하지 않습니다.
- 공유, 소셜, AI 분석·진단, 결제, 광고, 리워드, 푸시 알림 UI를 만들지 않습니다.
- 세계관을 위해 제품 범위 밖의 함선 지도, 아바타 꾸미기나 진행 등급을 추가하지 않습니다.

### 9.1 핵심 경험의 구현 연결

첫 실제 UI는 개발용 Mock 승객의 질문→작성→저장→다시 읽기입니다([D-TECH-038~049 · L222–233](./DECISIONS.md#111-구현상태복구)). 탑승은 운영 경로에 연결하며 동의/생성을 우회한 빌드를 배포하지 않습니다. 키보드·저장 배치·접근성·실패 시나리오는 각 흐름의 구현과 함께 검증합니다.

F10~F12의 route는 공통 장면 layout을 공유해 같은 질문과 작성 공간을 이어받습니다. 같은 방문의 질문 선택·읽던 위치는 06의 메모리 탐색 상태로 복원하고 본문/서버 정본은 복제하지 않습니다. F20의 읽던 위치를 바꾸는 최신 목록은 04 IX-042에 따라 상단에 돌아왔을 때 적용합니다.

## 10. 에셋과 디자인 원본

첫 질문/작성의 최소 자원과 후속 장식을 분리합니다. 장식·브랜드 서체의 지연/실패가 질문·입력·완료를 막거나 사용 중인 레이아웃을 밀지 않게 하며, 구체 로딩 경계와 성능 증거는 [06 §10.5 · L643–651](./06_FRONTEND_SPEC.md#105-시각-자원-로딩과-실패-격리)와 Asset Manifest를 따릅니다(D-TECH-049).

에셋의 상태와 권리는 [에셋 매니페스트 · L1–10](../../design/assets/ASSET_MANIFEST.md)에서 추적합니다([D-UI-007 · L31](./DECISIONS.md#2-ui-overview-결정)).

- 상태가 `사용 승인`인 에셋만 운영 빌드에 포함합니다.
- 로고의 확보·제작 출처·사용 권리 상태는 Asset Manifest에서 확인합니다.
- 일반 조작 아이콘은 ARCA가 직접 제작한 픽셀 아이콘을 사용하고 외부 아이콘 팩을 추가하지 않습니다. 격자·선 굵기·표시 크기는 [02 §8.2 · L397–417](./02_DESIGN_SYSTEM.md#82-아이콘-체계)를 따릅니다. JOY·SEMA·기억 조각의 도메인 시각과 장면 원본은 ARCA 방향 안에서 탐색합니다. 플랫폼이 직접 그리는 아이콘은 예외입니다(D-TECH-053).
- MVP에서는 사운드를 사용하지 않습니다. 픽셀 역할에는 공식 Neo둥근모 `v1.601` Regular WOFF2를 self-host하고, 사용자 응답·장문에는 공식 Pretendard `v1.3.9` Regular WOFF2를 self-host합니다. 미지원 글리프 fallback을 보장합니다([D-UI-032 · L89](./DECISIONS.md#6-시각-표현과-탐색), [D-UI-103 · L279](./DECISIONS.md#114-현행-ui와-입력-표시)).
- 배경은 생성 도구로 제작할 수 있습니다. 제작 시 UI와 맞출 팔레트·픽셀 밀도·대비·텍스트 안전 영역을 지정하고, 결과물과 선별 CMP를 같은 화면에서 비교합니다. 생성 이력·규격·출처는 Asset Manifest, 시각 통합 기준은 [02 §1.4 · L49–56](./02_DESIGN_SYSTEM.md#14-서로-다른-출처의-시각-통합)를 따릅니다.
- 큰 이미지와 픽셀아트는 초기 화면에 필요한 최소 리소스만 번들에 포함하고 나머지는 지연 로딩합니다.
- 픽셀 에셋은 [Design System §8 · L368–432](./02_DESIGN_SYSTEM.md#8-픽셀아트아이콘에셋)의 정수 배율·배경/전경 분리·장면별 기준 위치·실제 컨테이너 안전 영역과 용량 예산을 따릅니다([D-UI-040 · L97](./DECISIONS.md#6-시각-표현과-탐색)).

### 비교 시안과 시각 채택

Figma와 코드 프로토타입을 모두 시각 탐색 도구로 허용합니다. 핵심 표현은 **F10 → F11 → F12의 동작하는 비교 시안**으로 채택합니다([D-TECH-025 · L88](./DECISIONS.md#6-시각-표현과-탐색)).

- 비교 시안의 제작·시각 채택 상태는 [02 §13.3 · L674–683](./02_DESIGN_SYSTEM.md#133-남은-시각-채택-작업), 화면별 검증 결과는 [03 §10 · L948–974](./03_SCREENS_SPEC.md#10-권장-시작안검증할-결과채택-상태)에서 관리합니다.
- 비교 범위는 F10의 질문·작성 행동, F11의 공간 연결, F12의 저장 마무리, F10 완료 홈과 F21 읽기 구성이며 서체 역할·입력 명도·기록편을 포함합니다. 한 번에 비교할 차이를 명시하고 합성된 짧은 응답·긴 응답과 같은 질문을 사용합니다([D-UI-057~D-UI-066 · L119–127](./DECISIONS.md#8-핵심-경험과-화면별-위계)).
- 인트로는 건너뛰기를 포함한 6장면입니다(D-UI-089). F03 단일 진행, F13 복사 우선, F20 월 구획의 결과 검증도 [03 §10 · L948–974](./03_SCREENS_SPEC.md#10-권장-시작안검증할-결과채택-상태)의 조건으로 연결합니다. 배치 대안의 권한은 [00 §7.1 · L143–163](./00_INDEX.md#71-결정-강도와-자율-탐색)을 따릅니다.
- 비교 증거에는 읽기 쉬움, 짧게 써도 충분하다는 인상, 질문부터 저장까지의 연결감과 남은 문제를 기록합니다. 작은 화면·200% 글자·키보드·Reduced Motion을 함께 확인하고 iOS·Android 실제 토스 환경에서 검증합니다.
- 시각 채택은 제품 책임자가 비교 결과와 추천안을 확인해 정합니다. 승인된 방향 안의 값 조정은 [00 §7.1 · L143–163](./00_INDEX.md#71-결정-강도와-자율-탐색)을 따릅니다.
- 채택본마다 Figma 프레임 또는 코드 경로·버전 중 **하나의 기준 원본**을 기록하고 다른 표현물은 파생본으로 표시합니다. 현행 UI의 기준 원본은 코드이며 경로는 02 §13.3이 기록합니다.
- Figma를 사용할 때는 사용자 소유 `ARCA / MVP` 파일에 원본을 둡니다. 코드 원본을 선택한 범위에서 Figma 파일 생성·전체 복제는 필수 조건이 아닙니다.
- 필드·동작·문구·API·검증의 권위는 담당 명세에 있습니다. 채택한 시각 값은 02의 토큰·컴포넌트에 통합하고, 원본 위치·권리·승인 상태는 Asset Manifest에 기록합니다.
