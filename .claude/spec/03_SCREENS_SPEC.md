## 1. 적용 범위와 결정 강도

### 1.1 이 문서가 소유하는 것

15개 F 화면의 필수 정보·상태·진입/이탈·주/보조 행동·CMP 조합·스크롤/포커스와 검증할 결과를 소유합니다. 화면별 원본은 §4~7, 공통 보호 조건은 §8입니다.

### 1.2 이 문서가 소유하지 않는 것

동작·문구는 [04 §6 · L342–362](./04_INTERACTIONS_AND_COPY.md#6-화면별-상호작용-인벤토리), API는 [05 §4 · L126–148](./05_API_SPEC.md#4-15개-화면과-오퍼레이션-연결), 라우트·캐시·보관 구현은 [06 §11 · L661–681](./06_FRONTEND_SPEC.md#11-15개-화면-구현-책임-인벤토리)을 참조합니다. 최종 에셋·법무 원문·고객센터 연결값은 이 문서에서 확정하지 않습니다.

### 1.3 강도 적용

[00 §7.1 · L143–163](./00_INDEX.md#71-결정-강도와-자율-탐색)과 [D-TECH-024·D-TECH-026 · L87](./DECISIONS.md#6-시각-표현과-탐색)을 적용합니다.

| 강도 | 이 문서의 대상 | 적용 방식 |
|---|---|---|
| 필수 계약 | 화면 범위와 제품이 정한 진입·이탈, 필수 정보, 데이터 보호, 날짜·저장·삭제 결과, 한 화면 최대 하나의 Primary, 상태 보존, 320px·큰 글자·포커스·플랫폼 경계 | 변경하려면 담당 SSOT와 승인된 새 결정을 함께 갱신 |
| 조정 가능한 기본값 | 토큰 범위 안의 간격·타입 크기·surface 장식 강도, 상태 영역의 세부 여백, 작은 화면에서의 자연스러운 줄바꿈 | 필수 계약·승인 방향을 보존하며 비교·조정하고 채택값을 02와 원본에 반영 |
| 권장 시작안·탐색 가능한 표현 | 각 화면의 위→아래 배치와 묶음, F01 장면 수·구도, JOY 형상, F10~F12의 공간 연결, 기억 기록편, F20 월 구획과 행의 면·구분선 | §10의 검증할 결과를 만족하는 대안을 합성 데이터로 비교하고, 실제 기기 검증 뒤 채택 배치·기준 원본·에셋 상태를 기록 |

`확정`은 필수 계약·설계 방향과 권장 시작안이 승인됐다는 뜻입니다. 각 절의 위→아래 배치는 비교를 시작할 기본안이며, §10의 결과를 보존하는 다른 묶음·배치도 탐색할 수 있습니다. 필수 정보나 행동을 없애거나 제품 전이를 바꾸는 권한은 포함하지 않습니다. 현재 채택본이 없는 표현은 제작·검증 완료로 취급하지 않습니다.

## 2. 공통 화면 계약

### 2.1 플랫폼과 앱 셸

1. 앱인토스 필수 Navigation은 모든 화면의 플랫폼 영역입니다.
2. Navigation 바로 아래에서 `CMP-001 PixelAppShell`을 시작하고 앱 소유 공통 헤더를 중복 배치하지 않습니다.
3. `CMP-003 PixelCanvas`가 전체 배경과 최대 폭 정렬을 담당합니다.
4. 화면마다 `CMP-002 ScreenTitle` 하나를 실제 `h1`으로 둡니다. 초기 라우트 포커스는 이 제목으로 이동합니다. F01은 이 제목을 시각적으로 숨기고, F12는 시각적으로 숨긴 `h1` 대신 보이는 완료 결과 제목으로 초기 포커스를 옮깁니다.
5. `CMP-025 RootFloatingTabs`(오늘·기록·설정)는 루트 F10·F20·F30에만 표시하고 F30 닉네임 편집 중에는 숨깁니다. 하위 화면, 입력, 인트로, 전체 삭제, 오류에서는 표시하지 않습니다. 현재 탭을 다시 누르면 페이지 맨 위로 스크롤합니다. F10·F20 제목 오른쪽에는 `CMP-016 MemoryCount`를 두고 F30에는 두지 않습니다(D-UI-094).
6. 화면 내 Back, Android Back과 플랫폼 Navigation은 하나의 라우트 계층을 사용합니다. 열린 Dialog·Sheet를 먼저 닫고 하위 화면에서 부모로 돌아간 뒤 루트에서 플랫폼 종료 정책을 적용합니다.

### 2.2 폭·스크롤·고정 영역

- 최소 검증 폭은 320 CSS px, 최대 콘텐츠 폭은 480px입니다. 기본 gutter는 20px, 359px 이하는 16px입니다.
- 각 화면은 세로 문서 흐름 하나를 주 스크롤로 사용합니다. 페이지 가로 스크롤과 본문 안의 불필요한 중첩 스크롤을 만들지 않습니다.
- Textarea는 페이지 안에서 내용에 맞춰 확장하고 고정 높이 상한 뒤 내부 스크롤로 전환하지 않습니다.
- F10·F20의 공식 루트 탭 외곽은 하단 고정입니다. 콘텐츠 끝에는 탭과 Safe Area만큼 여유 공간을 둡니다.
- F02의 탑승 행동과 F03의 진행 행동은 문서 흐름 안에 둡니다. F11·F22의 저장은 문서 흐름 안 inline 하나이며, 저장 행동은 한 벌만 노출·조작·포커스 가능해야 합니다([D-UI-059 · L121](./DECISIONS.md#8-핵심-경험과-화면별-위계)).
- Overlay 자체는 필요할 때 내부 세로 스크롤을 가질 수 있으나 배경 문서 스크롤을 잠그고 종료 뒤 이전 위치를 복원합니다.

### 2.3 정보·서체·surface

- 화면 제목·짧은 JOY Label·조작은 픽셀 서체, 질문·답변·설명·날짜·카운터 등 읽기 본문은 본문 서체(Pretendard)를 사용합니다. 크기는 02 §4의 세 종류만 사용합니다.
- 사용자 입력·응답 발췌·응답 전문·닉네임 입력값, 장문 정책·오류 설명은 본문 서체를 사용합니다.
- 질문→작성→저장은 낮은 명도로 연결하고 작성에는 잉크색 `CMP-005 RecordPanel`을 기본으로 합니다.
- 정책 전문처럼 지속해서 읽는 긴 문서는 밝은 document 문맥을 선택할 수 있습니다.
- 주요 행동·도메인 장면에는 픽셀 형태를 집중하고, 읽기·보조 영역은 plain surface와 여백으로 구분할 수 있습니다.
- 한 화면 상태에서 Primary는 최대 하나이며 없어도 됩니다. F21은 읽기 자체가 목적이므로 수정·삭제를 보조로 둡니다. 복사는 F13 날짜 변경 직후의 주 복구 행동이며, 화면별 역할을 따릅니다. 질문 전환과 삭제는 secondary, ghost 또는 danger 역할을 사용합니다.

### 2.4 상태 표시 원칙

| 상태 | 유지할 콘텐츠 | 표시 위치·CMP | 가능한 행동 |
|---|---|---|---|
| 최초 Loading | 아직 신뢰할 수 없는 데이터 대신 화면 골격 | 전체 시작은 CMP-021, 부분 대기는 대상 위치 CMP-021·020 | 중복 행동 없음 |
| 화면 전체 Error | 입력이 없는 조회 화면에서는 안전한 설명과 오류 식별 정보 | 본문 첫 상태 영역의 CMP-022 | 최대 하나의 주 복구 행동과 필요한 고객센터 보조 행동 |
| 부분·행동 Error | 기존 입력과 이미 불러온 콘텐츠 | 실패한 필드·버튼·목록 끝 가까이 CMP-020 | 명시적 재시도 또는 안전한 복귀 |
| Empty | 제품상 빈 컬렉션이 존재하는 F20에만 적용 | 목록 자리의 CMP-022 | 화면 내 행동 없음; 오늘 이동은 루트 탭 |
| Mutation 중 | 입력·선택·대상 문맥 유지, 실행 control 크기 유지 | 실행 행동의 Loading + 가까운 CMP-020. 진행 문구·대기 보조 행동은 0.5초를 넘길 때만 표시하고 성공으로 떠나는 동안 처리 중 표시 유지(D-UI-104) | 중복 실행 금지, 임의 자동 재시도 금지 |
| 오프라인 | 입력·임시본·이미 표시한 콘텐츠 유지 | 실패한 대상 가까이 CMP-020, 초기 진입 실패는 CMP-022 | 연결 복구 뒤 사용자 재시도 |
| 세션 만료 | 현재 입력과 읽던 문맥 유지 | 자동 복구 중 실행 위치, 재실패 시 CMP-020 | F11·F22 저장은 Flow가 정한 1회 자동 재시도; 다른 세부 범위는 05로 인계 |
| 날짜 변경 | 현재 입력을 오늘 질문에 자동 전용하지 않음 | F11은 F13으로 전이, F10은 오늘 데이터 재조회 결과 위치 | 복사 또는 오늘로 이동 |

Loading과 Disabled는 같은 의미로 합치지 않습니다. Error 때문에 사용자 응답·닉네임·질문별 임시본·이미 불러온 목록을 지우지 않습니다. 차단 Overlay가 열린 동안 Toast를 겹치지 않습니다.

### 2.5 접근성·키보드·Reduced Motion

- 모든 독립 조작은 최소 44×44 CSS px, 포커스 표시는 2px·3:1 이상을 만족합니다.
- 320px와 200% 글자 확대에서 정보·행동 손실 없이 한 열로 reflow합니다.
- 보이는 위→아래 순서와 DOM·포커스 순서를 일치시킵니다. 질문 우선 화면에서는 화면 제목 다음 현재 질문이 첫 콘텐츠 읽기 대상입니다.
- F03·F11·F22·F30의 입력 포커스 시 Label, 커서, 상태·오류, 글자 수와 저장 행동까지 페이지 스크롤로 도달할 수 있어야 합니다.
- 키보드가 닫혀도 입력값, 선택 질문과 스크롤 문맥을 유지합니다. 키보드를 닫은 동일한 Android Back 입력으로 화면까지 연속 이탈하지 않습니다.
- F01은 정지 장면과 같은 서사 텍스트, F10의 질문 전환은 즉시 교체, F12는 즉시 완료 정지화면으로 Reduced Motion을 지원합니다.
- 일반 상태는 한 polite live region에서 한 번 알리고 즉시 대응이 필요한 저장 불가·차단 오류만 assertive로 알립니다.

### 4.2 F01 — 인트로

**목적과 근거**  
[인트로 서사 원문 · L1–41](../../docs/ARCA_INTRO_STORY.txt)의 세계관·항해 이유·JOY·기억을 6장면으로 전달합니다. 원문 전체 펼쳐 읽기는 제공하지 않습니다. 원문의 ‘또 다른 나를 만나면, 우리는 무슨 이야기를 해야 할까’는 세계관 뒤 전환점인 4장면에 둡니다. 정확한 편집은 `04`가 소유합니다. 건너뛰기만으로 탑승 완료를 만들지 않습니다([Rules ON-01 · L34](../../docs/ARCA_MVP_RULES.md#2-최초-탑승과-승객), [OD-25](../../docs/ARCA_OPEN_DECISIONS.md), [Acceptance #1~#2 · L50–61](../../docs/ARCA_MVP_ACCEPTANCE.md#최초-탑승), [D-UI-089](./DECISIONS.md#8-핵심-경험과-화면별-위계)).

**진입·이탈·행동**

- 진입: F00의 신규 분기, F31 전체 삭제 성공
- 이탈: 마지막 장면의 탑승 준비 또는 어느 장면의 건너뛰기로 바로 F02, 플랫폼 종료
- Primary: 현재 장면의 다음 진행. 마지막 장면에서는 탑승 준비 역할로 바뀝니다.
- Secondary: 모든 장면의 건너뛰기
- 루트 탭·설정: 표시하지 않습니다.

**장면 구조**

| 장면 | 서사 범위 | 필수 텍스트 역할 | 에셋 상태 |
|---|---|---|---|
| 1/6 | 2999년 평행우주의 발견과 또 다른 나 | 세계관의 출발점 | AST-004 생성 이미지 적용, 코드 원본 fallback |
| 2/6 | 함선 ARCA와 생애만큼 긴 동면 항해 | 항해의 규모와 동면 | AST-004 생성 이미지 적용, 코드 원본 fallback |
| 3/6 | 엔지니어 소이와 JOY의 탄생 | 질문과 답으로 생애를 펼치는 JOY | AST-004 생성 이미지 적용, 코드 원본 fallback |
| 4/6 | 또 다른 나에게 들려줄 이야기 | 사용자가 항해에 참여할 이유(전환점) | AST-004 생성 이미지 적용, 코드 원본 fallback |
| 5/6 | 동면 중 JOY의 하루 한 질문과 기억 조각 | 질문에 남긴 말이 기억이 되는 과정 | AST-004 생성 이미지 적용, 코드 원본 fallback |
| 6/6 | 출항과 탑승 | 서비스 경험의 기대와 탑승 전이 | AST-004 생성 이미지 적용, 코드 원본 fallback |

위 6장면이 채택 구성입니다. 장면마다 한 가지 서사만 담고 본문은 두 문장 안으로 유지합니다. 장면 6만 출항 인사를 더해 세 문장입니다. [원문](../../docs/ARCA_INTRO_STORY.txt)은 장면 편집의 단일 원본이며 변경하지 않습니다.

**각 장면 위→아래 배치 (전체 화면 장면 + 하단 대화창)**

1. 상단: 현재 장면/전체 장면의 진행 정보와 건너뛰기 행동. 화면 제목(CPY-F01-001)은 시각적으로 숨긴 접근 가능한 제목
2. 장면(맨 아래 층): 화면 전체를 가장자리까지 덮는 배경 층. 진행 정보와 대화창은 이 층 위에 겹쳐 뜸. 생성 이미지는 정사각 원본 하나로 화면을 덮음. 세로 폰에서 보이는 가운데 띠의 대화창에 가리지 않는 위쪽에 핵심 사물을 두고, 넓은 화면(펼친 폴더블·태블릿)에서만 드러나는 좌우는 배경으로만 채움. 배율·정렬·crop은 02 §8.1, 격자·안전 띠는 AST-004를 따름. 장면 1은 즉시, 2~6은 유휴 시점에 불러오며, 로딩 전·실패 시에는 코드 원본을 정수 배율로 대화창 위 보이는 영역 가운데에 표시하는 정적 fallback
3. 하단 대화창: 장면 문장을 한 문장씩 실제 텍스트로 표시. 같은 장면의 다음 문장은 앞 문장을 대체함. 문장은 좌측 정렬, 어절 단위 줄바꿈, 줄 길이 균형(`text-wrap: balance`, 미지원 엔진은 어절 단위만)을 적용하고 글자가 표시되는 동안 줄바꿈 위치가 바뀌지 않음. 대화창 높이는 최소 두 줄이며 한 장면 안에서는 가장 긴 문장에 맞춰 고정하고, 짧은 문장은 세로 가운데에 둠. 이미지 안에 핵심 서사를 굽지 않음
4. 대화창 안 진행 조작: 문장이 완성되면 ▼ 표시
5. 탑승 준비: 마지막 문장 뒤 진행하면 대화창이 서서히 사라진 뒤 같은 자리에 `탑승하기` Primary만 서서히 표시하고 포커스를 옮김(02 §7.1, D-UI-104). 탭·클릭으로 진행했으면 포커스 링을 숨기고 다음 키 입력부터 보임(D-UI-101). 하단 높이는 F02·F03 Primary와 같음. 누르면 인트로가 바탕색으로 가라앉은 뒤 F02로 이동(02 §7.1, Reduced Motion은 즉시)

장면 영역 탭은 진행 조작과 같은 결과를 내는 보조 입력이며, 키보드·보조기술은 실제 진행 조작을 사용합니다. 핵심 서비스 설명은 F02에 함께 두며 건너뛰기 뒤 요약 확인 상태는 만들지 않습니다. 정확한 장면별 문장은 `04`가 소유합니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| Data | 현재 장면·문장, 진행 정보, 대화창 텍스트, 진행 조작·건너뛰기 | 문장 완성 → 다음 문장 → 다음 장면, 마지막은 F02 |
| 문장 표시 중 | 대화창에 한 글자씩 표시, 보조기술에는 완성 문장 제공 | 탭·Enter·Space·진행 조작으로 즉시 완성. 건너뛰기 가능 |
| 후속 에셋 Loading | 현재 텍스트와 조작을 유지하고 장면 자리만 정적 대기 | 기다리지 않고 진행·건너뛰기 가능 |
| 에셋 Error | 이미지 없이 같은 텍스트와 배경색 fallback | 진행 차단 없음 |
| Reduced Motion | 정지 장면과 완성된 문장을 즉시 표시, 글자 표시·장면 교체 이동 제거 | 같은 행동 제공 |
| 오프라인 | 번들에 있는 현재 서사와 fallback 유지 | F02까지 진행 가능, 서버 행동은 F02에서 처리 |
| F31 성공 뒤 진입 | 첫 장면과 같은 Data | 삭제 완료(CPY-F31-019)를 polite로 한 번 발표 |
| Empty·입력·Mutation | 해당 없음. 서사 원문은 번들 콘텐츠이고 입력·서버 변경이 없음 | 없음 |

대화창은 장면의 문장 중 가장 긴 쪽이 들어갈 높이를 유지해 문장 교체 때 흔들리지 않습니다. 큰 글자에서는 대화창이 위로 늘어나고 장면 영역이 줄어들며, 필요하면 같은 문서 흐름으로 스크롤합니다. 구도·crop·전경 위치의 채택은 [D-UI-040 · L97](./DECISIONS.md#6-시각-표현과-탐색)과 AST-004를 따릅니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-030, CPY-F01-001~006·013~018의 장면 편집·직접 건너뛰기

**진입·이탈·행동**

- 진입: F01 완료 또는 직접 건너뛰기, 외부 약관 전문에서 복귀
- 이탈: 승객 생성 성공 F03, Back F01, 플랫폼 종료
- Primary: 두 필수 동의가 모두 선택된 뒤 탑승 요청
- Secondary: 약관별 전문 열람(Checkbox Label 안의 밑줄 약관 이름)
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. `CMP-002 ScreenTitle`
2. 짧은 탑승 설명: 매일 질문에 답하고 기억 조각으로 저장하는 경험. 인트로 진입 경로와 관계없이 제공하며 추가 확인 행동을 만들지 않음
3. 기억 조각 장식(AST-006, 8 px/셀): 설명과 하단 묶음 사이 남은 공간의 가운데. 둘레 픽셀 빛 3겹이 3초 주기로 밝아지고 어두워짐(D-UI-091, Reduced Motion은 켜진 정지 상태)

4~7은 화면 하단 묶음으로 두어 F01 `탑승하기`·F03 `첫 질문 만나기`와 Primary 하단 높이를 맞춥니다. 고정 위치가 아니라 문서 흐름 안의 하단 정렬이며, 한 화면에 들어가지 않는 작은 화면·큰 글자에서는 내용 뒤로 이어집니다.

4. 서비스 이용약관 `CMP-012 PixelCheckboxRow`
5. 개인정보처리방침 `CMP-012 PixelCheckboxRow`
6. 생성 실패·오프라인 등 행동 가까이의 `CMP-020 InlineStatus`
7. 문서 흐름 안의 `CMP-007 PixelButton` Primary. 비활성 이유(CPY-F02-009)는 시각 문구 없이 접근성 설명으로만 연결

Checkbox Label의 밑줄 약관 이름은 전문을 열고 선택을 바꾸지 않으며, 나머지 Label 텍스트는 선택을 바꿉니다(02 §9.5). 전문은 플랫폼 또는 외부 문서 문맥에서 열며, 복귀 시 F02의 스크롤·두 선택 상태·실행 요소 포커스를 복원합니다. 실제 정책 원문과 URL은 현재 저장소에 없어 후속 법무 자료와 `04`로 인계합니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 미동의·부분 동의 | 두 항목의 독립 상태 | Primary 비활성, 전문 열람 가능 |
| 동의 완료 | 두 항목 유지 | Primary 활성 |
| 생성 중 | 선택 유지, 버튼 크기·Label 영역 유지 | 중복 실행 금지 |
| 생성 실패·오프라인 | 두 선택과 현재 스크롤 유지, 버튼 가까이 오류 | 사용자 재시도, Back 가능 |
| 외부 문서 복귀 | 열기 전 선택·스크롤·포커스 문맥 복원 | 계속 동의 가능 |
| Empty·키보드·날짜 변경 | 해당 없음. 컬렉션·입력·날짜 종속 화면이 아님 | 없음 |

320px·큰 글자에서는 Label이 여러 줄로 이어지며 약관 이름 조작은 Label 흐름 안에 남습니다. CTA는 고정하지 않으며 사용자가 필수 정보를 지나 도달하게 합니다.

**후속 인계**

- 법무: 이용약관·개인정보처리방침 원문, 버전과 실제 URL
- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-018·031, CPY-F02-001~016의 동의·복구·실패·외부 복귀
- `05`: 동의 버전과 승객 생성의 원자적 계약
- `06`: 외부 문서 복귀 상태와 포커스 복원

### 4.4 F03 — 탑승 완료 및 닉네임

**목적과 근거**  
생성된 승객 코드와 이미 완료된 탑승을 확인하고, 한 번의 진행으로 선택형 닉네임 처리와 첫 SEMA 이동을 연결합니다. 섹션·원본 익명 식별키·성별·연령·프로필 이미지는 표시하지 않습니다([Rules ON-04~ON-06 · L37–39](../../docs/ARCA_MVP_RULES.md#2-최초-탑승과-승객), [Product Decision OD-12 · L41](../../docs/ARCA_OPEN_DECISIONS.md#2026년-9월-12일-승인된-제품-변경), [Acceptance #4·#7·#8 · L50–61](../../docs/ARCA_MVP_ACCEPTANCE.md#최초-탑승), [D-UI-056 · L118](./DECISIONS.md#8-핵심-경험과-화면별-위계)).

**진입·이탈·행동**

- 진입: F02의 승객 생성 성공
- 이탈: 진행 Primary로 닉네임 처리 후 바로 F10, 플랫폼 종료
- Primary: 첫 질문으로 진행. 정규화 후 빈 입력이면 건너뛰기, 유효한 입력이면 저장 성공 뒤 이동
- 정상 상태에는 별도 닉네임 저장·건너뛰기 버튼이나 처리 완료 뒤 두 번째 Primary를 만들지 않습니다. 확정 저장 실패·오프라인 미전송 뒤에는 04 IX-035의 `닉네임 없이 계속하기`를 Secondary로 제공합니다.
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. `CMP-002 ScreenTitle`
2. 탑승 완료의 짧은 상태(`승객 코드가 배정됐어요. 닉네임은 선택이에요.`): 한 줄(320px 기준)로 유지
3. `CMP-006 InsetPanel`: 승객 코드. 복사 행동 없음
4. `CMP-009 PixelField`와 `CMP-010 PixelTextField`: 선택형 닉네임 Label·입력·도움말·글자 수·오류를 한 묶음으로 좁게(8px) 붙임
5. 화면 하단 묶음: 입력·저장 상태의 `CMP-020 InlineStatus`
6. 화면 하단 묶음: 첫 질문으로 진행하는 Primary(F01·F02 Primary와 같은 하단 높이)와 확정 실패·미전송에서만 추가되는 닉네임 없이 진행 Secondary

빈 입력은 정상 선택이므로 Primary를 활성화합니다. 비어 있지 않은 유효하지 않은 입력은 오류를 알리고 이동하지 않습니다. 사용자가 입력을 직접 비우면 닉네임 없이 진행할 수 있습니다. 별도 완료 상태 없이 F10으로 이동하며, 닉네임 처리가 F02의 탑승 완료를 되돌리지 않습니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 초기·빈 닉네임 | 승객 코드, 선택형 입력, 활성 Primary | 한 번 진행으로 F10 |
| 유효한 입력 | 입력 원문과 field 상태 | 한 번 진행으로 저장 성공 뒤 F10 |
| 유효하지 않은 입력 | 입력 원문과 field 오류 | 이동하지 않음; 수정하거나 직접 비운 뒤 진행 |
| 저장 중 | 승객 코드와 입력 유지 | 진행·입력 변경의 경쟁 실행 방지 |
| 저장 확정 실패·오프라인 미전송 | 입력과 승객 코드 유지, field/행동 가까이 오류 | 재시도 또는 명시적 닉네임 없이 진행. 진행 선택 뒤 편집값 폐기·추가 요청 없이 F10 |
| Empty·페이지네이션·날짜 변경 | 해당 없음 | 없음 |

키보드가 열린 동안 입력·오류·행동까지 페이지 안에서 스크롤할 수 있어야 합니다. 진행 성공 후 F10 제목으로 라우트 포커스를 옮기며 중간 완료 제목은 만들지 않습니다. 정확한 검증·알림 시점은 `04`가 정합니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-001~003·008·018·035, CPY-F03-001~019의 입력·단일 진행·실패·포커스
- `05`: 닉네임 변경 operation과 서버 검증
- `06`: 단일 진행·중복 실행 방지와 한글 조합·이모지 문자 계산

## 5. 오늘의 SEMA와 응답

### 5.1 F10 — 오늘의 SEMA

**목적과 근거**  
미응답일 때는 질문과 작성 행동을 가깝게 제공하고, 응답 완료일 때는 저장 당시 질문과 완료 상태, 오늘 기록 진입만 가볍게 제공합니다(OD-28). 기본·대체 질문 선택과 오늘의 응답 상태를 이해한 뒤 작성 또는 오늘 기록으로 이동하게 합니다([Rules SE-01~SE-03·SE-06~SE-09·AR-09 · L49–57](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema), [Acceptance #9~#11·#20·#33~#34 · L63–71](../../docs/ARCA_MVP_ACCEPTANCE.md#질문-선택), [D-UI-057·D-UI-062 · L119](./DECISIONS.md#8-핵심-경험과-화면별-위계)).

**진입·이탈·행동**

- 진입: F00의 탑승 완료 분기, F03의 단일 진행 성공, F12의 오늘 복귀, F13의 오늘 이동, F10 루트 탭
- 이탈: 미응답은 선택 질문으로 F11, 응답 완료는 해당 F21, 기록 탭은 F20, 설정 탭은 F30, 플랫폼 종료
- Primary: 미응답이면 응답 작성 시작, 저장 결과 미확인이면 결과 확인(F11), 응답 완료면 내 기억 조각 상세
- Secondary: 미응답의 기본·대체 질문 전환, 조건부 지난 임시본 진입
- 고정 영역: `CMP-025 RootFloatingTabs`

**미응답 Data 상태 위→아래 배치**

1. `CMP-002 ScreenTitle`과 오른쪽 `CMP-016 MemoryCount`
2. `CMP-013 SemaSignalPanel`의 캡슐 구성: 화면 전체 투명 캡슐 배경(유리 너머 시간대 하늘) 위의 반투명 디스플레이 안에 짧은 JOY Label·실제 KST 날짜 → 현재 질문. 날짜는 디스플레이 상단의 보조 caption이며 질문이 시각적 중심
3. 같은 디스플레이 안의 행동 묶음: 응답 작성 `CMP-007 PixelButton` Primary와 `CMP-014 QuestionSwitchAction` Secondary. 묶음은 질문과 한 단계 더 띄우고 두 행동 사이는 그만큼 좁혀 디스플레이 높이를 늘리지 않음. 디스플레이 위(테두리→JOY Label)와 아래(`다른 질문 보기`→테두리) 여백은 위 여백에 맞춰 같게 둠(D-UI-099·101)
4. 보존된 지난 날짜 임시본이 있을 때만 `CMP-006 InsetPanel`과 보조 진입
5. 루트 탭을 가리지 않는 콘텐츠 끝 여유 공간
6. Safe Area 위 `CMP-025 RootFloatingTabs`

질문과 행동 묶음 사이에 메타·누적 수·지난 임시본을 끼우지 않습니다. 저장 결과 미확인 상태에서는 같은 디스플레이의 행동 묶음 자리에 미확인 상태 문구와 결과 확인 Primary만 두고 질문 전환을 숨깁니다(04 IX-036). 큰 글자에서도 문서를 스크롤해 모든 정보에 도달할 수 있어야 하며 첫 viewport에 넣기 위해 질문을 자르지 않습니다.

**응답 완료 Data 상태 위→아래 배치**

1. 같은 제목과 오른쪽 누적 수
2. 같은 캡슐 배경 위 디스플레이: 서문 내부 상단의 실제 KST 날짜 → 저장 당시 선택 질문. 보이는 질문 Label 없이 기존 접근성 이름 유지
3. 디스플레이 안 기억 조각 표지와 완료 문구(`오늘의 기억 조각을 남겼어요.`)를 가로 가운데에 둠(D-UI-101). 응답 원문·발췌는 표시하지 않고 F21에서 읽음
4. 디스플레이 안에서 해당 F21로 이동하는 Primary
5. 조건부 지난 임시본 진입, 콘텐츠 끝 여유 공간과 루트 탭

응답 완료에서는 질문 전환·새 작성 행동을 숨기고, 수정·삭제·날짜 변경 후 오늘의 실제 상태와 일치시킵니다(D-UI-097). 선택 질문은 저장 당시 스냅샷을 사용합니다. 현재 SEMA 조회값으로 저장한 질문을 바꾸지 않습니다.

미응답 진입에서는 기본 질문을 먼저 표시합니다. 질문 전환은 기본과 대체 사이에서만 명시적으로 제공하고 segmented control·swipe·carousel·세 번째 질문 요청을 사용하지 않습니다. 질문을 바꾸면 Primary가 선택된 질문으로 F11을 엽니다.

지난 임시본 진입을 선택하면 `CMP-018 PixelSheet`에서 만료되지 않은 날짜·질문별 임시본 목록을 보여 줍니다. 하나를 선택하면 F13으로 이동합니다. 이 목록은 저장된 기억 조각이나 오늘 답변에 합치지 않습니다([D-UI-048 · L106](./DECISIONS.md#7-화면-구조)).

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 초기 Loading | 제목과 캡슐 디스플레이 안의 정적 윤곽·하나의 로딩 상태, 누적 수 미표시 | 루트 탭의 안전한 이동 정책은 04·06에서 정함 |
| 미응답·기본 | 기본 질문, 보조 메타, 누적 수 | 질문 전환, F11 |
| 미응답·대체 | 대체 질문, 보조 메타, 누적 수 | 기본으로 복귀, F11 |
| 응답 완료 | 저장 당시 질문과 보조 메타, 완료 문구, 누적 수. 응답 발췌 없음 | 해당 F21; 질문 전환·새 작성 없음 |
| 지난 임시본 있음 | 현재 SEMA를 유지하고 캡슐 디스플레이 아래 조건부 보조 영역 | Sheet → 선택한 F13 |
| 최초 Error·오프라인 | 신뢰할 오늘 데이터가 없으면 CMP-022 | 재조회; 둘 다 없는 SEMA Empty 화면은 만들지 않음 |
| 표시 후 재조회 실패 | 현재 질문·응답 상태·누적 수를 제거하지 않고 콘텐츠 아래 CMP-006 안의 CMP-020 | 사용자 재시도 |
| 미확인 저장에서 복귀·재실행 | 저장 당시 선택 질문, 디스플레이 안 저장 결과 미확인 문구 | 04 IX-036의 결과 확인으로 F11, 같은 날짜 배포 단위의 새 저장·질문 전환은 결과 확인 또는 IX-041의 인증된 종료 정리 뒤 현재 상태에 따라 허용 |
| 날짜 경계 | 기존 날짜를 오늘처럼 유지하지 않고 오늘 상태를 재확인 | 정확한 감지·재조회는 05·06으로 인계 |
| Reduced Motion | 질문을 이동 없이 즉시 교체 | 같은 선택·포커스 상태 유지 |
| 시간대 | 캡슐 유리 너머 하늘만 기기 현지 시각의 새벽 05–08·낮 08–17·노을 17–20·밤 20–05시 팔레트 | 진입·포그라운드 복귀 때만 판정, 표시 중 전환·모션 없음. 질문·날짜·상태 판정과 무관 |

질문·메타데이터·누적 수는 고정 높이를 사용하지 않습니다. 200% 글자에서 누적 수와 제목이 겹치면 누적 수를 다음 행으로 내릴 수 있으나 현재 상태의 읽기 위계와 DOM 순서를 유지합니다. 미응답은 질문, 완료는 저장 당시 질문과 완료 문구가 먼저입니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-006·015·018·027·029·033~034·036·038, CPY-F10-001~039의 질문·완료·임시본 Sheet
- `05`: 오늘 SEMA·응답 상태·저장 당시 질문·누적 수·임시본 목록에 필요한 operation; 구체 DTO는 해당 문서에서 확정
- `06`: 날짜 경계, Sheet 상태, 질문 선택, 오늘 응답 상태의 수정·삭제·날짜 변경 동기화와 캐시 소유
- `08`: F10→F11→F12 비교 시안과 실제 기기 검증

F10의 모든 상태에서 발신자·SEMA 코드 목록을 표시하지 않고 날짜는 디스플레이 안에서 한 번만 보여 줍니다. SEMA 식별자·snapshot 데이터는 유지합니다. 캡슐 배경은 질문을 받는 공간(인트로 장면 6 다음, 덮개가 닫힌 투명 캡슐 안에서 관측 돔을 올려다보는 시점)이며 본문과 함께 스크롤하고, 이미지 로딩 전·실패 시에는 그리지 않습니다. 글자·조작은 반투명 디스플레이·면 위에만 둡니다(D-UI-095, AST-012).

### 5.2 F11 — 응답 작성

**목적과 근거**  
선택한 질문에 1~2,000자의 응답을 작성하고 질문별 로컬 임시본을 보존한 뒤 명시적으로 서버 저장합니다. F10의 질문을 읽던 집중을 작성과 완료까지 이어갑니다([Rules SE-05·SE-06·SE-08·SE-09, AN-01~AN-05 · L53–57](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema), [Acceptance #12~#18·#36~#37 · L63–71](../../docs/ARCA_MVP_ACCEPTANCE.md#질문-선택), [D-UI-045·D-UI-058~D-UI-060 · L104](./DECISIONS.md#7-화면-구조)).

**진입·이탈·행동**

- 진입: F10에서 기본 또는 대체 질문을 선택해 응답 시작
- 이탈: 최초 저장 성공 F12, 날짜 변경 F13, Back F10, 플랫폼 종료
- Primary: 현재 질문과 응답 저장
- Secondary: 현재 질문 바로 아래의 기본·대체 질문 전환, Back
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. Back과 `CMP-002 ScreenTitle`
2. `CMP-013 SemaSignalPanel`: JOY 표지·짧은 JOY Label → 현재 선택 질문 전문. F10의 위치·폭·JOY 표시 문맥을 이어받음
3. 같은 패널 안 질문 바로 아래의 `CMP-014 QuestionSwitchAction`
4. `CMP-005 RecordPanel`
5. `CMP-009 PixelField` 안의 `CMP-011 PixelTextarea`
6. Field help row: 기기 임시 보관 상태와 글자 수. 임시본을 복원한 직후에는 같은 자리에 복원 문구를 두고, 입력하면 보관 상태로 바뀜. 서버 기록 저장과 명확히 구분
7. Field 오류 또는 저장 실패의 `CMP-020 InlineStatus`
8. 저장 `CMP-007 PixelButton` Primary: 문서 흐름 안 inline. 결과 미확인·운영 중지·실패 상태에서는 같은 자리의 복구 행동과 복사·나중에 확인하기 보조 행동(04 IX-036)
9. 저장 행동 아래 가운데 정렬의 짧은 비공개·기기 보관 안내. `나만 볼 수 있어요.`(자물쇠)와 보관 문장을 각각 한 행으로 둠(D-UI-104)

질문 전환 완료는 화면에 문구를 남기지 않고 접근성 발표로만 알립니다(04 IX-006, D-UI-099).

질문을 전환하면 현재 본문을 해당 질문 임시본으로 보존하고 전환한 질문의 임시본을 같은 위치에 표시합니다. 전환 시 Textarea 높이는 새 본문에 맞춰 다시 계산하되 페이지 스크롤과 포커스가 질문·입력 관계를 잃지 않아야 합니다. 세부 저장 시점과 포커스는 `04`·`06`이 소유합니다.

Textarea는 빈 상태에서 3~4줄 기본 공간으로 시작하고 내용에 따라 페이지 안에서 확장합니다. 복원된 임시본이 길면 첫 표시부터 본문에 맞게 확장합니다.

F10~F12는 [06 §3.3 · L193–206](./06_FRONTEND_SPEC.md#33-composition-root)의 공통 장면 layout으로 같은 질문 identity의 위치·폭을 이어받습니다. F10→F11은 그 아래 작성 영역이 열리는 연결을 비교하며 본문을 장면용 DOM으로 복제하지 않습니다. 라우트·제목 포커스·루트 탭의 표시 계약은 유지하며, 키보드·큰 글자·줄바꿈에 맞춰 자연스럽게 reflow합니다. Reduced Motion에서는 같은 정보와 정적 배치로 즉시 전환하고 입력 가능 시점을 장식 모션 완료에 묶지 않습니다.

F11·F22의 짧은 보관 안내(04 CPY-F11-006·F22-006)는 저장 행동 아래에 항상 표시합니다. Placeholder와 정상 보관 상태는 04의 간결한 채택 문구를 사용합니다.

비공개 안내와 로컬 보관 상태는 분리합니다. ‘나만 볼 수 있는 기록’, ‘이 기기에 임시 보관됨’은 의미를 설명하는 예시이며 정확한 문구는 `04`가 소유합니다. 로컬 쓰기 성공을 확인한 경우에만 보관 완료를 알리고, 실패하면 본문을 유지하며 미보관 상태·복구를 안내합니다. 서버 저장 완료는 서버 성공 후에만 알립니다([D-UI-060 · L122](./DECISIONS.md#8-핵심-경험과-화면별-위계)).

**상태**

F11·F22의 질문은 body 크기의 얇은 서문, 입력은 4줄 시작의 native textarea입니다. 입력을 둘러싼 RecordPanel은 바깥 면·padding 없이 입력 경계만 둡니다. 글자 수는 IME 중에도 즉시 바뀌며 오류·저장·보관 확정은 04 IX-001을 따릅니다.

### 5.3 F12 — 기억 조각 기록 완료

**목적과 근거**  
F11에 머무는 동안 확인한 최초 서버 저장 성공 뒤 사용자의 말이 보존됐다는 연결감을 결정 조각 표지와 누적 수 롤, 완료 정지화면으로 전달합니다. 첫 기억과 반복 기록의 마무리를 구분합니다([Rules AN-06·AN-08·AR-09 · L71–73](../../docs/ARCA_MVP_RULES.md#4-응답과-기억-조각), [D-UI-030·D-UI-058·D-UI-061 · L56](./DECISIONS.md#3-design-system-결정)).

**진입·이탈·행동**

- 진입: F11에 있는 동안 확인한 최초 저장 성공만 허용. 이탈 후 확인한 성공은 IX-036에 따라 현재 화면을 동기화하며 강제 F12 이동 없음
- 이탈: 항해 기록은 F20, 오늘 복귀는 F10. 첫 기억은 기록 Primary·오늘 Secondary, 반복 기록은 오늘 Primary·기록 Secondary
- 두 이동은 진입 즉시 조작 가능
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. 시각적으로 숨긴 화면 `h1`
2. F11 RecordPanel의 자리·폭과 공간적으로 연결되는 `CMP-004 ScenePanel`
3. `CMP-024 MemoryFormation`: 결정 조각 표지(AST-006)가 계단식으로 한 번 밝아진 뒤 정지
4. 서버 저장 성공 결과 제목. 초기 포커스 대상. 반복 기록도 보조 문구 없이 같은 제목만 둔다
5. `CMP-016 MemoryCount`: 확인된 수는 이전 수(N−1)에서 새 수(N)로 자물쇠 다이얼처럼 바뀐 자리만 한 칸 굴러 올라감. 기록편 형성이 끝나는 시점에 함께 멈추며 접근성 이름은 처음부터 새 수(02 §7.3, D-UI-104). 미확인이면 같은 자리에 확인 대기·실패 문구
6. 누적 수 미확인·재조회 이력이 있을 때만 `CMP-020 InlineStatus`와 정보 다시 불러오기 ghost 행동
7. 현재 완료 문맥에 맞는 `CMP-007 PixelButton` Primary
8. 나머지 이동 Secondary

2~5의 장면은 남는 세로 공간의 가운데, 7~8의 이동 버튼은 문서 흐름 안에서 화면 하단에 둡니다. F01~F03 하단 Primary와 같은 방식이며 고정 위치가 아닙니다. 작은 화면·큰 글자에서는 내용 뒤로 이어집니다(D-UI-099).

위계 판별은 [Rules AN-08 · L73](../../docs/ARCA_MVP_RULES.md#4-응답과-기억-조각)을 따릅니다. 서버가 확인한 활성 누적 수로 판단하며 별도 생애 최초 저장 플래그를 만들지 않습니다. 두 이동 버튼이 처음 조작 가능할 때 누적 수가 미확인이면 오늘 복귀를 우선하고 첫 기억이라고 추정하지 않습니다. 같은 방문 동안 늦은 조회로 버튼 위치·이름·강조를 바꾸지 않으며, 버튼 활성화를 조회 때문에 늦추지 않습니다. 완료 결과는 누적 수 확인 상태와 무관하게 계속 표시합니다(04 IX-039).

저장한 응답 원문·발췌는 F12에 표시하지 않습니다. 기록편·결과·누적 수로 저장 사실만 전하고, 내용은 F21에서 읽습니다(D-UI-102). 응답을 연출 에셋·로그·외부 생성 도구로 전달하지 않습니다. 구체적인 기록편 형상·픽셀 개수·형성 단계는 고정하지 않습니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 진입 | 결정 조각 형성·누적 수 롤과 완료 결과·두 이동 | 이동 즉시 가능 |
| 첫 기억 완료 | 성공 결과·정적 기록편·누적 수 | F20 Primary, F10 Secondary |
| 반복 기록 완료 | 같은 완료 정보, 별도 문구 없음 | F10 Primary, F20 Secondary |
| 누적 수 확인 중·실패 | 저장 성공과 확인된 정보 유지, 해당 위치만 정적 대기 또는 CMP-020 | 정보 재조회와 두 이동; 첫 조작 시 미확인이면 오늘 우선으로 고정, 재저장·연출 재실행 없음 |
| Reduced Motion | 형성 과정을 생략하고 즉시 완료 정지화면 | 동일 행동 |

서버 성공 뒤 `softMedium` 햅틱을 한 번 best-effort로 호출하며 수정 저장에는 사용하지 않습니다. 스크린 리더에는 연출 프레임이 아니라 완료 결과만 한 번 알립니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-020~021·027·029·039, CPY-F12-001~019의 완료 분기
- `05`: 저장 성공과 정합한 활성 누적 수 확인 계약; 구체 DTO·조회 분리는 해당 문서에서 결정
- `06`: CSS 단계 애니메이션, 완료 분기·햅틱 adapter와 실패 격리
- `08`: 최대 2초·Reduced Motion·키보드·iOS/Android, #33·#35~#36 증거
- Asset Manifest AST-006·009: 채택한 기록편과 정적 fallback

F12의 장면에는 큰 바깥 면 없이 작은 기록편·완료 제목·누적 수만 둡니다.

### 5.4 F13 — 작성 중 날짜 변경·지난 임시본

**목적과 근거**  
날짜가 바뀌어 신규 저장할 수 없는 본문을 보존하고 복사 또는 오늘의 SEMA로 이동하게 합니다. 만료 전 지난 임시본 재열람에도 같은 화면을 사용하며 오늘 질문에 자동 입력하지 않습니다([Rules SE-05, AN-02·AN-05 · L53](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema), [Acceptance #15·#18 · L73–83](../../docs/ARCA_MVP_ACCEPTANCE.md#응답과-날짜), [D-UI-048·D-UI-063 · L106](./DECISIONS.md#7-화면-구조)).

**진입·이탈·행동**

- 진입: F11 저장의 날짜 변경 결과, F10의 지난 임시본 Sheet에서 선택
- 이탈: 오늘의 새 신호는 F10, Back은 진입 문맥에 따라 F11 또는 F10
- 날짜 변경 직후 Primary: 본문 복사. Secondary: 오늘의 SEMA로 이동, Back
- 지난 임시본 재열람 Primary: 오늘의 SEMA로 이동. Secondary: 본문 복사, Back
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. Back과 `CMP-002 ScreenTitle`
2. `CMP-004 ScenePanel`: 진입 문맥 설명(날짜 변경으로 새로 저장할 수 없음 또는 지난 날짜에 남긴 내용) → 작성 날짜(지난 KST 날짜) → 작성할 때 받은 질문
3. `CMP-005 RecordPanel` 안의 read-only `CMP-011 PixelTextarea`: 보존 원문 전체를 선택·복사 가능하게 표시
4. 같은 패널의 field help: 기기 보관 상태. 기기 보관 성공과 만료 일시를 확인한 경우 마지막 수정 시각에서 7일 뒤인 실제 KST 날짜·시각을 덧붙이고, 보관 실패·미확인에는 만료 일시를 숨기고 복사·유실 위험 안내 유지
5. 복사 결과의 `CMP-020 InlineStatus`
6. 내용 복사: 날짜 변경 직후 Primary, 재열람 Secondary
7. 오늘의 SEMA 이동: 날짜 변경 직후 Secondary, 재열람 Primary

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 날짜 변경 직후 | 본문·질문·기기 보관 상태·지난 날짜, 보관 성공 시에만 실제 만료 일시 | 복사 Primary 또는 F10 Secondary |
| 보존 임시본 재열람 | 선택한 임시본의 같은 정보 | 복사 또는 F10 |
| 복사 중·성공·실패 | read-only 본문 유지, 복사 실패 시 직접 선택 방법을 화면과 접근성에 표시 | 재시도 또는 안내된 직접 선택·복사 |
| 오프라인 | 로컬 임시본과 만료 정보 유지 | 복사·F10 이동 가능, F10 조회는 별도 처리 |
| 만료 | 만료된 본문을 계속 표시하지 않음 | F10으로 안전하게 안내; 정확한 문구는 04 |
| 로컬 조회 중·실패 | 제목·Back과 정적 윤곽 또는 CMP-020 오류 | 오늘의 SEMA 이동 Primary |
| 서버 저장·페이지네이션·삭제 | 해당 없음. 과거 미작성 응답 생성 기능을 제공하지 않음 | 없음 |

F13의 본문을 오늘 질문에 옮기는 행동은 제공하지 않습니다. 플랫폼 Clipboard 채택과 브라우저 fallback은 `06`이 결정하되 복사라는 제품 행동은 유지합니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-022·027~028·034·037·040, CPY-F13-001~020의 복사·만료·Back
- `05`: 서버 날짜 판정과 날짜 변경 오류
- `06`: 임시본 목록·만료 청소·Clipboard adapter·진입 문맥

## 6. 항해 기록

### 6.1 F20 — 기록 목록

**목적과 근거**  
저장 당시 질문 일부와 날짜를 읽고 기록을 선택하면 상세에서 자기 응답 전문을 읽게 합니다. 목록에는 응답 발췌를 표시하지 않습니다. 월 구획으로 시간이 흐른 문맥을 제공합니다. AI 요약·재작성·감정 해석·인벤토리형 타일을 사용하지 않습니다([Rules AR-01·AR-02·AR-09 · L82–90](../../docs/ARCA_MVP_RULES.md#5-항해-기록과-삭제), [Product Decision OD-11 · L40](../../docs/ARCA_OPEN_DECISIONS.md#2026년-9월-12일-승인된-제품-변경), [Acceptance #21·#33·#38 · L85–93](../../docs/ARCA_MVP_ACCEPTANCE.md#기록과-삭제), [D-UI-039·D-UI-064 · L96](./DECISIONS.md#6-시각-표현과-탐색)).

**진입·이탈·행동**

- 진입: 기록 루트 탭, F12의 항해 기록 행동, F23 삭제 성공
- 이탈: MemoryRow는 F21, 오늘 탭은 F10, 설정 탭은 F30, 플랫폼 종료
- Data의 주 행동: 전체 너비 MemoryRow 선택
- Empty: 행동 없이 제목으로 완결. 오늘 이동은 루트 탭이 제공
- 보조 행동: 추가 로딩 실패 뒤 재시도, 깊이 내렸을 때 맨 위로
- 고정 영역: `CMP-025 RootFloatingTabs`, 그 위 오른쪽의 `CMP-026 ScrollTopButton`(한 화면 높이 넘게 내렸을 때만)

**Data 상태 위→아래 배치**

1. `CMP-002 ScreenTitle`과 오른쪽 `CMP-016 MemoryCount`
2. 전체 너비 한 열 목록. 실제 작성 날짜의 KST 연월이 바뀔 때 작은 월 제목과 여백으로 구획
3. 각 `CMP-015 MemoryRow`: 보조색 날짜 → 흰 본문 서체의 저장 당시 질문 일부. F10·F21과 같은 날짜 위·질문 아래 순서(D-UI-104). 응답 발췌는 표시하지 않음
4. 목록 끝이 가까워지면 다음 20개를 자동으로 불러옴(무한 스크롤). 불러오는 동안 마지막 행 아래 `CMP-027 PixelLoader`, 실패하면 같은 위치의 `CMP-020 InlineStatus`와 재시도(D-UI-105)
5. 추가 페이지를 한 번 이상 불러온 뒤 끝에 도달한 경우만 목록 종료 상태
6. 루트 탭을 위한 콘텐츠 끝 여유 공간
7. Safe Area 위 `CMP-025 RootFloatingTabs`

일반 MemoryRow에는 SEMA 코드·응답 발췌·응답 Label을 반복 표시하지 않습니다. 질문 일부는 04 IX-027의 80 EGC·2개 논리적 줄 기본값을 사용하고 `받은 질문`은 접근성 이름에 유지합니다. 목록 API의 발췌 필드는 05 계약대로 유지하되 화면·접근성 이름에는 넣지 않습니다. 행마다 상세 API를 추가 호출하는 전제는 두지 않습니다.

월 구획은 기존 최신순과 행별 날짜를 유지한 표시 그룹입니다. 연도를 함께 구분하고, 같은 월이 다음 20개 페이지로 이어질 때 제목을 중복하지 않습니다. 기록하지 않은 날·월의 빈칸이나 출석률을 만들지 않습니다. 마지막 행이 삭제된 월의 제목도 제거하며 편집·추가 로딩 뒤 스크롤 문맥을 보존합니다. 정확한 날짜 Label은 `04`, 페이지 경계의 그룹 조합은 `06`이 소유합니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 최초 Loading | 제목·탭 유지, 목록 자리 정적 윤곽 | 중복 조회 없음 |
| Data 1~20건 | 누적 수와 최신순 행 | F21 |
| 추가 Loading | 기존 행과 스크롤 위치 유지, 마지막 행 아래 CMP-027 | 기존 행 선택 유지 |
| 추가 Loading 실패 | 기존 행 유지, 실패 위치 상태. 자동으로 다시 부르지 않음 | 해당 위치 재시도. 커서 무효면 같은 재시도로 최신 첫 페이지부터 다시 불러옴 |
| 깊은 위치의 최신 목록 준비 | 안내 없이 보류하고 읽던 위치 유지 | 맨 위로 돌아오면(CMP-026 포함) 04 IX-042에 따라 새 chain 적용. 후보 실패·무효화 시 폐기 |
| Empty | 목록 자리 CMP-022의 장식과 제목으로 완결, 행동·중복 사용법 설명 없음 | 루트 탭으로 F10 |
| 최초 Error·오프라인 | CMP-022와 재조회 | F20 재조회 |
| 표시 후 오프라인 | 기존 행·누적 수 유지, 목록 끝 상태 | 연결 뒤 재시도 |
| 수정 뒤 복귀 | 캐시 갱신, 질문·날짜 유지; 다시 연 상세에서 새 응답 확인 | 해당 F21 또는 목록 탐색 |
| 개별 삭제 뒤 복귀 | 성공한 행 제거와 누적 수 반영 | 목록 유지 |
| 전체 삭제 성공 뒤 | F20에 남지 않음 | F01 |

한 행 전체를 하나의 hit area로 사용하고 내부에 중첩 버튼을 두지 않습니다. 200% 글자에서 질문·날짜가 자연스럽게 세로로 늘어나며 날짜를 고정 우측 열로 만들지 않습니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-023·027~029·042, CPY-F20-001~025 중 질문·날짜·월 구획·자동 추가 로딩·맨 위로
- [05 · L1–24](./05_API_SPEC.md): OP-010 cursor·20개 정렬·발췌와 OP-005 활성 누적 수, 수정·삭제 후 일관성
- [06 · L1–26](./06_FRONTEND_SPEC.md): 월·연도·페이지 경계의 그룹 조합, 독립 count 조회, 캐시 갱신과 스크롤 복원

### 6.2 F21 — 기록 상세

**목적과 근거**  
저장 당시 질문 전문을 짧은 서문으로 먼저 읽고 자기 응답 전문에 집중하게 합니다. 읽는 것 자체로 완결되며 수정·삭제는 보조 행동입니다([Rules SE-09, AN-07, AR-03·AR-09 · L57](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema), [Acceptance #19·#23·#33 · L73–83](../../docs/ARCA_MVP_ACCEPTANCE.md#응답과-날짜), [D-UI-065~D-UI-066 · L126–127](./DECISIONS.md#8-핵심-경험과-화면별-위계)).

**진입·이탈·행동**

- 진입: F20 MemoryRow, F10의 오늘 기록, F22 수정 성공, F23 삭제 취소·실패
- 이탈: 수정은 F22, 삭제는 F23 논리 상태, Back은 F20
- Primary: 없음. 주 기능은 다시 읽기
- Secondary: 수정, danger-text: 삭제. 미확인 수정 요청이 있으면 04 IX-036에 따라 결과 확인으로 F22에 재진입하고 새 수정·삭제는 확정까지 보류
- 루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. Back과 `CMP-002 ScreenTitle`
2. 서문 안쪽 상단의 작성 날짜 → 저장 당시 질문 전문. 날짜는 `작성일` 접두 문구 없이 caption으로 한 번 표시하며 `<time datetime>` 의미를 유지. 질문의 보이는 Label 없이 기존 접근성 이름 유지, 접기·말줄임 없음
3. `CMP-005 RecordPanel`: 응답 Label(`내 답변`)과 사용자 응답 전문을 가장 큰 주 읽기 영역으로 제공. 본문 서체, 선택·복사 가능. 공백만 있는 응답이면 그 사실을 보조 문구로 표시
4. 조회·행동 오류의 `CMP-020 InlineStatus`. 수정 여부와 수정 저장 성공은 보이는 문구로 표시하지 않고 성공만 접근성으로 한 번 발표(D-UI-105)
5. 본문 아래 관리 보조 그룹: 수정 `CMP-007 PixelButton` Secondary와 삭제 `danger-text` 밑줄 행동. 결과 미확인 요청이 있으면 같은 자리가 결과 확인 행동으로 바뀜

운영 중 질문 원문이 수정되거나 SEMA가 교체돼도 저장 당시 질문 스냅샷을 표시합니다. 응답·질문 전문은 말줄임하지 않습니다. 질문이 DOM에서 먼저 읽히고 응답이 화면의 주 읽기 영역이 되도록 서체 크기·여백을 둡니다. 수정·삭제를 실행하지 않아도 화면의 목적을 완료할 수 있고, 보조 행동의 대비·타깃·포커스는 유지합니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| Loading | 제목·Back과 상세 윤곽 | 완료 후 Data |
| Data | 저장 당시 질문 서문, 응답 전문, 날짜 | 계속 읽기 또는 보조 행동 F22·F23 |
| 최초 Error·오프라인 | 상세 자리 CMP-022 | 재조회 또는 Back |
| 표시 후 행동 Error | 읽던 전문과 스크롤 유지, 행동 가까이 상태 | 재시도 |
| 수정 성공 복귀 | 갱신된 응답 전문. 성공은 보이는 문구 없이 한 번 발표 | 계속 읽기·재수정·삭제 |
| 삭제 실패 복귀 | 삭제되지 않은 기존 상세 유지 | 다시 삭제 가능 |
| Empty·페이지네이션·키보드 | 해당 없음. 단일 읽기 화면이며 편집은 F22가 담당 | 없음 |

동시 삭제·not-found처럼 제품 문서가 결과를 정의하지 않은 서버 상태는 새 화면 동작을 추정하지 않고 `05`로 인계합니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-018·025·029·036, CPY-F21-001~018의 읽기·수정·삭제 진입
- `05`: 저장 당시 질문 snapshot과 상세 조회 결과, 동시 변경 오류
- `06`: F20/F10 진입 문맥과 Back·스크롤 복원

### 6.3 F22 — 응답 수정

**목적과 근거**  
기존 응답 전문을 편집하고 수정 저장 성공 뒤 F21 전문과 F10·F20 캐시(발췌 필드 포함)를 갱신합니다. 과거 응답도 수정할 수 있지만 선택 질문을 바꾸지는 않습니다([Rules AN-01~AN-04·AN-07, AR-03·AR-09 · L66–72](../../docs/ARCA_MVP_RULES.md#4-응답과-기억-조각), [Acceptance #19·#33 · L73–83](../../docs/ARCA_MVP_ACCEPTANCE.md#응답과-날짜)).

**진입·이탈·행동**

- 진입: F21 수정
- 이탈: 수정 성공 F21, Back F21
- Primary: 수정 저장. 결과 미확인·다른 곳에서 먼저 수정됨 상태에서는 같은 자리의 결과 확인·최신 내용으로 다시 수정
- Secondary: Back, 변경이 있을 때 `수정 내용 버리기`(확인 Dialog 뒤 수정 임시본만 제거하고 F21 복귀, 04 IX-024)
- 질문 전환·루트 탭·설정: 표시하지 않습니다.

**위→아래 배치**

1. Back과 `CMP-002 ScreenTitle`
2. 읽기 전용 서문: 작성 날짜 → 저장 당시 질문 전문. F21 서문과 같이 날짜를 위에 `작성일` 접두 없이 caption으로 표시(D-UI-104)
3. `CMP-005 RecordPanel`
4. `CMP-009 PixelField` 안의 기존값 `CMP-011 PixelTextarea`
5. 임시 저장 상태와 글자 수. 수정 임시본을 복원한 직후에는 같은 자리에 복원 문구
6. field·저장 오류의 `CMP-020 InlineStatus`
7. 기준이 다른 이전 수정 임시본이 있을 때만 별도 읽기 전용 `CMP-005 RecordPanel`: 안내·이전 본문·복사·`이전 수정 내용 버리기`(확인). 현재 입력에 자동 적용하지 않음

입력의 초기 높이·내용 확장·키보드 대응, 기기 임시 보관·서버 저장 구분과 inline 저장은 F11과 동일합니다([D-UI-059~D-UI-060 · L121–122](./DECISIONS.md#8-핵심-경험과-화면별-위계)). F22에는 QuestionSwitchAction을 두지 않습니다.

### 6.4 F23 — 기억 조각 한 건 삭제

**목적과 근거**  
삭제 대상을 분명히 확인하고 한 번의 사용자 확인 뒤 되돌릴 수 없는 개별 삭제를 실행합니다([Rules SE-10, AR-04·AR-09 · L58](../../docs/ARCA_MVP_RULES.md#3-오늘의-sema), [Acceptance #20·#22·#33 · L73–83](../../docs/ARCA_MVP_ACCEPTANCE.md#응답과-날짜)).

F23은 별도 전체 페이지를 추가하지 않고 **F21 위에 열린 주소 지정 가능한 논리적 modal 상태**로 구현합니다. `CMP-017 PixelAlertDialog`의 파괴 행동 계약을 그대로 사용합니다([D-UI-016·D-UI-031 · L44–57](./DECISIONS.md#3-design-system-결정)).

**진입·이탈·행동**

- 진입: F21 삭제 행동, 삭제 결과 미확인 요청이 있는 F21 진입
- 이탈: 취소는 F21, 성공은 F20, 실패는 기존 F21 문맥
- danger 행동: 삭제 확정
- 안전 행동: 취소. 초기 포커스도 취소에 둡니다.

**Dialog 위→아래 배치**

1. 삭제 확인 제목
2. 되돌릴 수 없다는 설명 한 줄. 대상 날짜·질문·응답 본문은 반복하지 않고 배경 F21 서문이 대상 문맥을 제공(D-UI-104, OD-30)
3. 삭제 실패 시 Dialog 또는 복귀한 F21의 `CMP-020 InlineStatus`; 정확한 위치 우선순위는 04
4. 한 줄 두 버튼: 왼쪽 취소 안전 행동, 오른쪽 삭제 danger 행동(F30 닉네임 편집의 취소·저장과 같은 배치; 좁은 폭·큰 글자에서는 줄바꿈). 삭제 결과 미확인 상태에서는 결과 확인·나중에 확인하기를 세로로 둠

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| 확인 | 배경 F21의 읽던 위치와 대상 문맥 유지 | 취소 또는 삭제 |
| 삭제 중 | 대상 정보 유지, danger control Loading | 중복 실행·Dismiss 방지 범위는 04 |
| 실패·오프라인 | 대상과 F21 상세를 삭제하지 않음 | F21에서 재시도 가능 |
| 성공 | 해당 행과 누적 수를 목록 상태에서 제거 | F20 |
| 오늘 기록 삭제 | 성공 후 F10은 기본 질문 미응답 상태 | F20 이후 오늘 탭에서 다시 작성 가능 |
| Empty·키보드·페이지네이션 | 해당 없음 | 없음 |

Dialog가 닫히면 F21의 삭제 trigger로 포커스를 복원합니다. 성공 시 F20 제목으로 라우트 포커스를 이동합니다.

**후속 인계**

- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-016~018·025·029·036, CPY-F23-001~012의 확인·Dismiss·실패 복귀·결과 미확인

## 7. 설정·전체 삭제·시작 오류

### 7.1 F30 — 설정

**목적과 근거**  
승객 정보를 확인하고 닉네임을 변경하며 정책·고객센터·앱 정보와 모든 데이터 삭제에 접근합니다. 섹션·성별·연령·프로필 이미지·원본 익명 식별키·별도 문의 이메일을 표시하지 않습니다([Rules ON-05·ON-08, CS-01, DP-04 · L38–41](../../docs/ARCA_MVP_RULES.md#2-최초-탑승과-승객), [Product Decision OD-02·OD-07·OD-09 · L24–31](../../docs/ARCA_OPEN_DECISIONS.md#최근-닫힌-결정), [Acceptance #7·#8·#31 · L50–61](../../docs/ARCA_MVP_ACCEPTANCE.md#최초-탑승), [D-UI-051~D-UI-053 · L108–110](./DECISIONS.md#7-화면-구조)).

**진입·이탈·행동**

- 진입: 설정 루트 탭, F31 취소·Back, 외부 정책·고객센터에서 복귀
- 이탈: 오늘·기록 탭은 F10·F20, 정책 전문은 외부 문서, 문의는 앱인토스 고객센터, 전체 삭제는 F31. 루트이므로 화면 내 Back은 없고 Android Back은 루트 정책(04 IX-017)을 따릅니다.
- 화면 전체 Primary: 없음. 각 설정 행은 독립적인 보조 행동입니다.
- 닉네임 편집 상태 Primary: 닉네임 저장
- 고정 영역: `CMP-025 RootFloatingTabs`. 닉네임 편집 중에는 숨겨 키보드 위 입력·저장과 겹치지 않게 합니다.

**위→아래 배치**

1. `CMP-002 ScreenTitle`
2. **승객 정보 그룹**: 현재 닉네임 또는 승객 코드 호칭, 닉네임 편집 행동, 승객 코드
3. 닉네임 편집 시 같은 그룹 안에서 펼쳐지는 `CMP-009 PixelField`·`CMP-010 PixelTextField`, 한 줄 두 버튼(왼쪽 취소 Secondary, 오른쪽 저장 Primary; 좁은 폭·큰 글자에서는 세로). 입력 바로 아래 한 줄에 검증 오류(왼쪽)와 글자 수(오른쪽)만 보이며 F03과 같은 field 간격을 씀
4. **정책·지원 그룹**: 이용약관, 개인정보처리방침, 앱인토스 고객센터
5. **앱 정보 그룹**: 앱 버전
6. **위험 영역(데이터 관리 그룹)**: 삭제 범위 한 줄 설명과 모든 데이터 삭제 danger 진입

정책·지원 행동을 열지 못하면 같은 그룹 끝에 `CMP-020 InlineStatus`를 둡니다. 승객 정보 조회 중에는 그룹 자리에 정적 윤곽, 실패하면 그룹 안 `CMP-022`와 재시도를 둡니다.

네 그룹은 모두 같은 넓은 간격으로 구분하고, 각 그룹 제목 구분선에서 첫 콘텐츠 글줄까지의 거리도 같게 맞춥니다(D-UI-099·101). 복구 제약은 F02와 같이 서비스 이용약관에서 고지하며 F30에 별도 안내를 두지 않습니다(D-UI-098).

닉네임 입력은 기본 상태에 항상 펼치지 않습니다. 현재 값을 읽기 전용으로 보여 주고 편집 행동을 선택했을 때 같은 위치에서 field·저장·취소가 확장됩니다([D-UI-052 · L109](./DECISIONS.md#7-화면-구조)). 저장·취소가 완료되면 읽기 상태로 접고 trigger 문맥으로 포커스를 복원합니다.

두 정책 전문은 F02와 같은 플랫폼 또는 외부 문서 문맥에서 열고, 복귀 시 F30의 스크롤·편집 상태·실행 요소 포커스를 복원합니다. 고객센터는 제품 SSOT가 정한 앱인토스 단일 채널로 직접 연결합니다.

**상태**

| 상태 | 유지·표시 | 행동·연결 |
|---|---|---|
| Data·읽기 | 승객 정보, 정책·지원, 버전, 위험 영역 | 각 보조 행동 |
| 닉네임 편집 | 나머지 설정 유지, 같은 그룹 안 field 확장 | 저장·취소 |
| 닉네임 저장 중 | 입력과 설정 문맥 유지 | 중복 저장 금지 |
| 검증·저장 실패·오프라인 | 입력 유지, field 가까이 오류 | 수정·재시도·취소 |
| 외부 화면 복귀 | 스크롤·편집 상태와 포커스 복원 | 설정 계속 사용 |
| 세션 문제 | 읽기 가능한 기존 정보와 입력 유지 | 세부 갱신·복구는 05·06으로 인계 |
| Empty·페이지네이션·날짜 변경 | 해당 없음 | 없음 |

키보드가 열리면 확장된 field·오류·저장·취소를 가리지 않게 페이지를 스크롤합니다. 위험 영역은 고정 하단 CTA로 만들지 않습니다.

**후속 인계**

- 법무·운영: 정책 원문·버전·URL과 고객센터 실제 연결값
- [04 · L1–23](./04_INTERACTIONS_AND_COPY.md): IX-001~004·008~011·018, CPY-F30-001~035의 닉네임·정책·지원
- `05`: 승객 정보·닉네임 변경 operation
- `06`: 진입 루트 기억, inline 편집 상태와 외부 화면 복귀

### 7.2 F31 — 모든 데이터 삭제

**목적과 근거**  
활성 서비스 데이터와 로컬 데이터의 삭제 범위, 복구 불가와 보존 예외를 충분히 설명한 뒤 두 단계로 삭제를 확인합니다([Rules AR-05~AR-08 · L86–89](../../docs/ARCA_MVP_RULES.md#5-항해-기록과-삭제), [Product Decision OD-03 · L25](../../docs/ARCA_OPEN_DECISIONS.md#최근-닫힌-결정), [Acceptance #24·#25·#33 · L85–93](../../docs/ARCA_MVP_ACCEPTANCE.md#기록과-삭제), [D-UI-054 · L111](./DECISIONS.md#7-화면-구조)).

**진입·이탈·행동**

- 진입: F30 위험 영역
- 이탈: Back·1차 취소는 F30, 성공은 F01, 실패는 F30의 기존 상태 또는 F31의 안전한 상태
- F31 페이지 Primary danger: 최종 확인 Dialog 열기
- F31 페이지 Secondary: 취소·Back
- Dialog danger: 모든 데이터 삭제 확정
- Dialog 안전 행동: 취소. 초기 포커스도 취소에 둡니다.
- 루트 탭·설정: 표시하지 않습니다.

**1차 F31 화면 위→아래 배치**

1. Back과 `CMP-002 ScreenTitle`
2. `CMP-005 RecordPanel` 또는 document 문맥: CPY-F31-020~022의 삭제 대상 목록. 사용자 화면에는 구체적인 대상 명칭 사용
3. `CMP-006 InsetPanel`: CPY-F31-023~026의 증빙 목적·1년 보관·개별 항목 목록·제외 대상. 목록은 의미 있는 list로 제공하며 항목을 접어 숨기지 않음
4. `CMP-006 InsetPanel`: 삭제 대상이 포함된 백업은 복구에 쓰지 않고 요청일부터 최대 30일 안에 만료
5. 복구할 수 없다는 결과
6. 실패 상태를 표시할 `CMP-020 InlineStatus`
7. 한 줄 두 버튼: 왼쪽 취소 Secondary, 오른쪽 2차 확인을 여는 danger Primary(F23과 같은 배치, D-UI-104). 준비만 된 요청의 요청 끝내기처럼 행동이 셋이거나 결과 미확인 행동일 때는 세로

이전 삭제의 결과 확인·로컬 정리가 남은 삭제 복구 상태(06 §5 DELETION_RECOVERY)에서는 Back과 취소를 숨기고 결과 확인 또는 정리 재시도만 제공합니다. 삭제 중과 이 상태에서는 화면 이탈을 막습니다.

**2차 CMP-017 Dialog 위→아래 배치**

1. 최종 삭제 확인 제목
2. 삭제 대상과 비가역성의 짧은 요약
3. 한 줄 두 버튼: 왼쪽 안전한 취소, 오른쪽 삭제 danger 행동. 결과 미확인 상태의 확인·나중에 확인하기는 세로

1차 페이지는 정책을 읽는 문맥, 2차 Dialog는 마지막 실행 확인만 담당합니다. 긴 보존 정책을 Dialog에 다시 복제하지 않습니다.

### 8.1 저장·입력 보호

- F11·F22의 입력과 질문별 임시본은 저장 실패, 앱 종료, 오프라인과 세션 만료 때문에 지우지 않습니다.
- F11 최초 저장 성공은 해당 SEMA의 기본·대체 질문 임시본을 모두 제거하고 F12로 이동합니다.
- F22 수정 저장 성공은 수정 임시본을 제거하고 F21 전문과 F10·F20 캐시(발췌 필드 포함)를 갱신합니다.
- F13의 지난 임시본은 마지막 수정 후 7일까지 열람·복사하며 오늘 질문에 자동 삽입하지 않습니다.
- 전체 삭제 성공은 모든 로컬 임시본과 세션 캐시를 제거합니다. 실패·부분 결과에서는 성공한 것처럼 로컬 상태를 먼저 지우지 않습니다.

### 8.2 목록·삭제 보호

- F20 추가 로딩 중·실패에는 기존 MemoryRow와 스크롤 위치를 유지합니다.
- 개별 삭제 성공 뒤에만 F20 행·월 구획과 누적 수를 갱신하고 관련 F10·F12 발췌 캐시도 제거합니다. 실패하면 F21 상세를 유지합니다.
- 전체 삭제 성공 뒤 F01로 이동하며 F10/F12/F20/F21 캐시와 브라우저 히스토리에 삭제된 본문·발췌가 다시 나타나지 않아야 합니다.
- 모든 화면의 발췌·응답 전문·임시본은 로그·분석·오류 추적·시각 원본·외부 생성 도구에 남기지 않습니다.

같은 방문의 질문 선택·selection·scroll anchor·복귀 대상은 [06 §5.6 · L343–351](./06_FRONTEND_SPEC.md#56-navigationcontext의-수명과-복원)의 메모리 snapshot을 소비합니다. 본문/대상 revision·editVersion 검증 뒤 복원하며 아래 제목 포커스 계약을 대체하지 않습니다. 재조회가 사용 중인 상태를 덮지 않고 주체/권한/generation 변경·삭제 때 과거 문맥을 제거합니다.

### 9.1 화면과 API 연결 조건

- F02 성공은 OP-003의 ACTIVE 세션으로 F03을 이어가며 생성 응답 유실을 새 탑승으로 처리하지 않습니다.
- F10의 콘텐츠 교체는 같은 dailySemaId의 완료 상태를 유지합니다. 완료 문맥은 저장 당시 콘텐츠·질문이며 현재 미응답 질문과 섞지 않습니다.
- F11·F22·F23·F31의 실행 전 요청 종료와 오래된 결과 정리는 04 IX-041을 적용합니다. 사용자 행동은 기존 상태 영역에 배치하고 별도 필수 화면을 추가하지 않습니다. OP-015의 현재 상태에 따라 F10/F13/F20/F21 또는 현재 입력으로 연결합니다.
- F12의 수는 [05 §5.5 · L191–205](./05_API_SPEC.md#55-command-ticket과-결과)의 revision/관찰 시각을 지키고 과거 결과와 최신 본문을 섞지 않습니다. F20 질문 일부의 프로필 선택·예산은 04 IX-027의 조정 가능한 기본값입니다.
- F31은 이전 generation의 민감 로컬 자료를 정리하고 제한 token으로 ack를 시도한 뒤 최초 탑승으로 연결합니다. 다른 기기의 ack·새 탑승이 섞이면 [05 §6.7 · L341–373](./05_API_SPEC.md#67-op-007009-공통-command-lifecycle)에 따라 기존 영역만 제거합니다.
